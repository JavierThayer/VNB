## What was built and proven

**The generator.** `(relation R C)` is a slot kind of `declare-structure`: its conjunct of `IS-X` is
`R(s) in POWER(CARTESIAN(C s, C s))` (the honest typing, not the bare `R(s) in SET` the carrier slot gave),
and its arrow clause is

    forall([x1_ in pts(a), x2_ in pts(a)], [x1_, x2_] in rel(a) implies [f(x1_), f(x2_)] in rel(b))

with `f` the map of the carrier `C`. SETOID is now `(carriers PTS) (relation REL PTS) (property
is-equivalence REL PTS)`: one carrier, so `HOM-SETOID(a, b)` is the ordinary SEP of `FUN(PTS a, PTS b)`
by `IS-HOM-SETOID`, and `IS-HOM-SETOID(a, b, f)` reads "f is a setoid morphism from a to b". The
two-carrier hom-set branch of batch 39 is kept as generic code and pinned by a toy structure in the
suite; no library structure has two independent carriers any more.

**The laws** (`theorem-library/hom-kinds.scm`, the pairs-of-maps section replaced; one rule per kind, as
for `family`): `hom-setoid-member-iff`, `-id`, `-compose`, `-in-set`, and, with SETOID added to
`hom-functors.scm`'s list, `hom-setoid-post-type` and `-pre-type`. All six `proven modulo 0`, pages
grounded. SETOID is not in `hom-laws.scm`'s generic list: that driver closes an EQUATION at an
eigenvariable; the relation clause is an implication.

## What was found

1. **The certified loader drops the `;; qed` line of the first proof that FOLLOWS a certified skip in the
   same file** (`certificates.scm`: `skipping` is sampled before the form runs and the whole form's output is
   captured; the theorem is installed and its page grounded, only the line is missing). In `off` mode the
   line prints. A reader counting `;; qed` lines against `(qed` forms under `on` miscounts by one per
   such file. Recommended: route the qed line to the certificate console the way the "no certificate ...
   proving it" message is, one edit in `certificates.scm`, with a suite control.
2. **The suite cannot run from a certified band**: about 12 checks pin provenance `proven` and see
   `certified`, and a proof-reader check wants a theorem that RAN. The integration flow runs it from the
   exam band, so nothing is wrong today; the checks could accept `certified`.
3. **Tightening a slot's typing breaks the constructors.** A proof that builds an instance by hand proves
   each conjunct of `IS-X`; when a property already carries the typing (here `is-equivalence`), a kit helper
   that closes a structure predicate's typing conjunct from the proven property would have made both cone
   edits unnecessary. Owed (CLAUDE.md, STILL OWED).
4. **What the generator cannot say**: a heterogeneous relation (a subset of `C1 x C2`); the reflecting
   arrow (`x ~ y iff f x ~ f y`), which is one `declare-category!` away and was not wanted.
5. `is-equivalence` repeats the typing conjunct inside `IS-SETOID`: harmless, and the reason the cone
   fixes were cheap.
6. Loading `primitive-inferences.scm` onto a running band works only into `user-initial-environment`.
