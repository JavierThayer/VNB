VNB operator census

Auto-generated by (write-operators-md). Every registered operator head, classified per the VNB taxonomy.

An operator is a head symbol: a registered name that, applied to argument terms, forms a compound term (or, when it is a predicate, a proposition). Not every head is a symbol. Every applied term has a head — the expression in operator position — and that head may itself be a compound term rather than a name (the f in an application f(args), a variable of function type, a vnb-lambda abstraction). So head term is the general notion and operator is the special case where the head is a symbol. This census lists the operators — the symbols.

The VNB universe has SETS (the elements of SET), CLASSES, and further entities about which VNB makes no commitment. A term-forming operator is classified by WHAT IT DENOTES:

  • A function denotes an element of a set: specifically a set-function, an element of some FUN(A, B) with A,B sets. The numeric and analytic operators are functions: exp, sin, cos, sqrt, abs, conjugate, real-part, imag-part, magnitude, and the arithmetic + - * recip. vnb-lambda is the binder that constructs a set-function.
  • A functoid denotes something that is not required to be an element of SET. This is a large, somewhat amorphous category: the kernel set- and tuple-builders (union, sep, power, fun, image, …) whose arguments range over a proper class; every library constructor (matmul, mat-ring, the structure accessors, …); and the recursively-defined ones. Some functoids can be regarded as functions, but a functoid is not required to be one. lambdoid is the binder that constructs a functoid — the class-domain sibling of vnb-lambda. Application is implicit: writing f(args) denotes apply-functoid(f, args) when f is a functoid and apply-function(f, args) when f is a function — these two application operators are never written by hand. Whether an operator is a kernel primitive or a library definition is a matter of ORIGIN, recorded as metadata; it is not a VNB distinction and carries no semantic weight. A kernel set-former is a functoid exactly as a library constructor is.
  • A predicate is an operator whose application to argument terms is a proposition — an entity whose value is either true or false. The proposition and its truth value are two separate things in the mathematical universe: a predicate applied to terms always denotes a proposition, but the truth value of that proposition may not be known.

Every operator must be declared (a def-form, a recursion, or a characterizing axiom). An undeclared head is a defect.
